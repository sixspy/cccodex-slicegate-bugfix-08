- 版本：2026-11-17（落定后当天禁止改口）
- 适用仓：日切放行 `slicegate-bugfix-08`，仅约束本仓日切放行链路
- 选定路径：**甲路径**（唯一口径，后端常量 `CHOSEN_PATH = "甲"`，接口 `GET /api/policy/boundary` 同源输出）

## 一、两条候选路径与选型

| 路径 | 口径 | 本仓是否采用 |
|------|------|--------------|
| 甲 | 解冻与作废关前完整缓存**同一事务提交**并写入**待重裁**态；正式完整度仅重裁成功后写回 | **采用** |
| 乙 | 关前完整先落入只读历史快照表再清空现行完整度字段，解冻后按现行期望重裁通过才放行 | 不采用（仅留档，禁止混用） |

正确性口径只准贯彻解冻写路径（甲路径）一种，前后端与测试不得混入乙路径的快照表闸门口径。

## 二、甲路径状态机

```
未放行（完整/部分完整/待检）
  └─ 冻结 POST /api/slices/{id}/freeze
       → frozen=1，关前完整度封存进 preclose_completeness / preclose_snapshot（仅历史核对，不再当现行完整度）
  └─ 解冻 POST /api/slices/{id}/unfreeze   （同切片加锁串行）
       → 同一事务：frozen=0 且 completeness='待重裁'
       → 任一步骤失败：整体回滚，切片状态不变（失败闭）
  └─ 重裁 POST /api/slices/{id}/evaluate
       → 唯一的正式完整度回写点：按现行 row_count/expected_count 经 compute_completeness 裁决
       → 重裁结果为“完整”后，放行闸才允许通过
已放行：冻结、解冻、放行均拒绝并登记“解冻口径偏了”，解冻链路永不回改已放行态
```

## 三、硬不变量（违反即拦截并登记 `解冻口径偏了`）

1. **失败闭**：解冻写完整度先钉死失败闭——事务中途任何异常一律回滚，接口返回错误，绝不留下半解冻状态。
2. **口径唯一**：完整度只由 `compute_completeness` 一处计算；登记、重裁共用，禁止第二套算法。
3. **关前缓存作废**：解冻后现行完整度恒为“待重裁”；`preclose_completeness` 仅作历史展示，任何放行/裁决读路径不得再把它当完整。
4. **重裁才回写**：正式完整度仅重裁成功后由重裁写路径（evaluate）写回，解冻路径本身不产生“完整”结论。
5. **已放行态免动**：解冻不得顺带修改 `release_status`；UPDATE 语句带 `release_status!='已放行'` 条件，对已放行切片的解冻/冻结请求直接 409 并登记。
6. **并发串行**：同一候审切片两名值班同时抢解冻，进程内按切片加锁串行，数据库层 `BEGIN IMMEDIATE` + 条件 UPDATE 兜底；后到者收到 409“解冻争用：…”并在 `unfreeze_ledger` 登记 `解冻争用`，不得静默成功。
7. **重裁前禁放行**：放行闸对 `frozen=1` 与 `completeness='待重裁'` 一律 409 并登记偏离，杜绝拿关前缓存放行。

## 四、同源可核的五个视图

解冻台、切片详情、重裁目录、策略旁注、处置页不各自计算状态：

| 视图 | 数据源 |
|------|--------|
| 解冻台 / 切片详情 / 重裁目录 | `GET /api/slices` 同一份切片载荷（completeness、frozen、preclose_completeness 字段一致） |
| 策略旁注 | `GET /api/policy/boundary`（与本文件同版本、同口径） |
| 处置页 | `GET /api/ledger`（`unfreeze_ledger` 全量留痕：冻结入候/解冻/重裁回写/解冻争用/解冻口径偏了） |

只换提示文案而不改正文重裁字段（completeness 仍停留关前“完整”）视为验收失败：验收以数据库字段与重裁流水为准。
